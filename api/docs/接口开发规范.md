## 二、通用规范

### 2.1 URL 设计

```
/api/v1/{资源名复数}[/{id}][/{子资源}]
```

- 资源名用**复数小写**，多词用连字符：`/source-files`、`/instrument-datasets`
- 层级不超过两级：`/samples/{id}/transitions` 可以，`/batches/{id}/samples/{sid}/measurements` 不行——改用查询参数
- 动作型接口用子路径：`/measurements/{id}/supersede`、`/derived-results/recompute`
- 非 CRUD 的分析类接口放在 `/analysis/` 下：`/analysis/pair`

### 2.2 HTTP 方法与状态码

| 方法 | 用途 | 成功状态码 |
|---|---|---|
| GET | 查询，幂等 | 200 |
| POST | 创建 | 201 |
| PATCH | 部分更新 | 200 |
| PUT | 整体替换（仅用于明确语义） | 200 |
| DELETE | 删除 | 204 |

**关键约定：** HTTP 状态码表达协议层结果，业务状态码（`code`）表达业务层结果。两者同时返回，**前端以 `code` 为准**。

| HTTP | 含义 | 典型 code |
|---|---|---|
| 200/201/204 | 成功 | 0 |
| 400 | 参数格式错误 | 1001 |
| 401 | 未认证 / 令牌过期 | 2001 |
| 403 | 权限不足 | 2002 |
| 404 | 资源不存在 | 3001 |
| 409 | 唯一键冲突 | 3002 |
| 422 | 业务规则校验失败 | 4001 |
| 429 | 触发限流 | 5001 |
| 500 | 服务端错误 | 9001 |

### 2.3 统一响应包络

**所有接口（含错误）**返回同一结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "request_id": "9f8b7c6d-5e4f-3a2b-1c0d-9e8f7a6b5c4d",
  "timestamp": "2026-10-15T16:30:00+08:00"
}
```

错误示例：

```json
{
  "code": 1001,
  "message": "请求参数校验失败",
  "data": {
    "type": "https://ale-workbench.local/errors/validation-failed",
    "title": "Validation Failed",
    "status": 400,
    "code": 1001,
    "detail": "样品编码格式不正确",
    "instance": "/api/v1/samples",
    "errors": [
      {
        "field": "sample_code",
        "message": "样品编码格式不正确，应形如 W01-S01",
        "rejected_value": "W01 S01"
      }
    ]
  },
  "request_id": "9f8b7c6d-5e4f-3a2b-1c0d-9e8f7a6b5c4d",
  "timestamp": "2026-10-15T16:30:00+08:00"
}
```

`request_id` 由服务端生成并写入日志，排障时凭此定位。

### 2.4 数值类型约定（重要）

**数据库 DECIMAL 字段一律以字符串传输。**

| 数据库类型 | JSON 类型 | TS 类型 | Python 类型 |
|---|---|---|---|
| `DECIMAL(14,6)` | string | `string` | `Decimal` |
| `TINYINT(1)` | boolean | `boolean` | `bool` |
| `DATETIME` | string | `string` | `datetime` |
| `DATE` | string | `string` | `date` |
| `INT` | number | `number` | `int` |
| `JSON` | object | `Record<string,unknown>` | `dict[str,Any]` |

原因：膜厚 `289.690000` 这类值在 JavaScript 中转为 number 会精度失真。数据库存的是定点类型，传输层必须保持字符串。

契约中的字段标注 `x-db-type: decimal(14,6)`，代码生成器据此还原为 `Decimal`（Python）或 `string`（TS）。

**后端注意：** 用 Pydantic 的 `Decimal` 类型接收，不要用 `float`。响应序列化时 Decimal 需转为字符串（FastAPI 默认转 float，需自定义 `json_encoders`）。

### 2.5 时间格式

统一 ISO 8601，**含时区偏移**：

```
2026-10-15T16:30:00+08:00
```

日期用 `2026-10-15`。前端用 dayjs 处理，后端用 `datetime` + 时区。

### 2.6 分页

**偏移式分页**（数据量小，无需游标）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 页码，从 1 开始 |
| `size` | int | 20 | 每页条数，上限 200 |

响应：

```json
{
  "code": 0,
  "data": [ ],
  "meta": {
    "page": 1,
    "size": 20,
    "total": 137,
    "total_pages": 7,
    "has_next": true,
    "has_prev": false
  }
}
```

**注意：** 分页响应的 `data` 是数组，`meta` 与 `data` 平级。

### 2.7 排序与筛选

排序参数 `sort`，前缀 `-` 表示降序，多字段逗号分隔：

```
?sort=-created_at,batch_code
```

允许的排序字段在各接口文档中列出。传非法字段时忽略并返回 `1001` 警告，不报错。

筛选参数用资源字段名，多个筛选条件为 AND 关系。

### 2.8 版本管理

- 版本号在路径中：`/api/v1/`
- **向后兼容的新增**（加字段、加可选参数、加新端点）不升版本
- **不兼容变更**（删字段、改类型、改语义、改必填性）发布 `/api/v2`
- 旧版本保留至少 6 个月
- 响应头返回 `X-API-Version: 1.1.0`，便于排查

## 三、认证与权限

### 3.1 认证流程

采用**双令牌**：

```
1. POST /api/v1/auth/login       → { access_token, refresh_token }
2. 业务请求带 Authorization: Bearer <access_token>
3. access_token 过期（401 + code 2001）
4. POST /api/v1/auth/refresh     → 新 access_token
5. refresh_token 也过期 → 重新登录
```

| 令牌 | 有效期 | 用途 |
|---|---|---|
| access_token | 1 小时 | 业务请求 |
| refresh_token | 7 天 | 仅用于换新令牌 |

**安全要求：**
- 密码用 Argon2id 哈希，不落明文
- access/refresh JWT 绑定数据库可撤销会话；refresh 每次轮换，登出撤销会话并清除 cookie
- 登录失败不做用户存在性区分（统一返回"用户名或密码错误"）
- 登录接口限流：同一 IP 每分钟 10 次

### 3.2 角色与权限

三种角色：

| 角色 | 说明 |
|---|---|
| `admin` | 管理员。全部权限，含用户管理、删除、审计 |
| `operator` | 普通用户。可创建/编辑实验数据 |
| `viewer` | 只读用户。仅读取与导出 |

权限标识格式 `{资源}:{动作}`：

| 权限 | admin | operator | viewer |
|---|---|---|---|
| `sample:read` | ✓ | ✓ | ✓ |
| `sample:write` | ✓ | ✓ | ✗ |
| `sample:delete` | ✓ | ✗ | ✗ |
| `batch:write` | ✓ | ✓ | ✗ |
| `process:write` | ✓ | ✓ | ✗ |
| `measurement:read` | ✓ | ✓ | ✓ |
| `measurement:write` | ✓ | ✓ | ✗ |
| `measurement:supersede` | ✓ | ✓ | ✗ |
| `derived:read` | ✓ | ✓ | ✓ |
| `derived:write` | ✓ | ✓ | ✗ |
| `file:read` | ✓ | ✓ | ✓ |
| `file:write` | ✓ | ✓ | ✗ |
| `instrument:write` | ✓ | ✓ | ✗ |
| `finding:write` | ✓ | ✓ | ✗ |

| `chart:export` | ✓ | ✓ | ✓ |

前端通过 `GET /auth/me` 获取 `permissions` 数组控制按钮显隐。**但前端控制只是体验优化，后端必须独立校验。**

### 3.3 数据归属

`data_scope` 字段表示可见范围：

- `all` —— 全部数据（admin）
- `own` —— 自己拥有的批次与样品，样品所属批次也须可见（operator / viewer）

阶段 1 即执行 owner_user_id 隔离；无共享实现，无所有者记录仅 admin 可见。列表、详情、写入、分页总数与首页聚合均应用所有权约束。

## 四、数据可信度约定

**这一节是本工作台区别于通用 CRUD 系统的核心。** 数据库设计把科研数据治理规则固化进了结构，接口层必须保持这些语义。

### 4.1 查询默认值

| 接口 | 默认行为 | 理由 |
|---|---|---|
| `GET /measurements` | 只返回 `is_current=true` | 避免误用被取代的基线 |
| `GET /derived-results` | 只返回 `is_valid=true` | 避免使用已失效结果 |
| `GET /source-files` | `exclude_duplicates=true` | SRC-D 内嵌了 SRC-A/C 副本 |
| `GET /samples` | 不自动排除异常样品 | 但返回 `exclude_from_analysis` 供前端标识 |

当前测量列表默认含历史，以current/is_current显式筛选；include_superseded不是当前已实现参数。

### 4.2 必须处理的风险标记

后端在以下场景必须主动标记或告警：

**跨模型相减。** 创建 `derived_results` 时，服务端比较 before/after 两次测量的 `optical_model_id`。不同则 `model_consistent=false`，并在 `model_warning` 给出提示。**不接受客户端指定此字段。**

**取代链维护。** 调用 `/measurements/{id}/supersede` 时：
1. 原测量 `is_current=false`，写入 `supersede_reason`
2. 新测量 `supersedes_measurement_id` 指向原测量
3. 所有以原测量为 before 或 after 的 `derived_results` 置 `is_valid=false`

**排除样品的统计防护。** 任何聚合统计接口应默认排除 `exclude_from_analysis=true` 的样品，或在响应中标注包含了异常样品。

**工艺模式隔离。** `/charts/comparison` 必须校验所请求样品的 `process_mode` 是否一致。混入 `full_cycle` 与 `pre_expose_then_react` 时在 `warnings` 中告警。

### 4.3 NULL 的语义

工艺步骤中的未知参数**必须保持 null，不得用配方标称值填充**。

```json
{
  "o3_generator_o2_flow_set_sccm": null,
  "o3_generator_o2_flow_measured_sccm": null,
  "o3_concentration": null
}
```

`null` 表示"未记录"，与"记录为 0"或"等于标称值"是不同的语义。前端展示时应显示为"未记录"而非空白或 0。

## 八、错误处理约定

### 8.1 后端

业务错误用自定义异常，由统一异常处理器转为标准格式：

```python
class BusinessError(Exception):
    def __init__(self, code: int, message: str, status: int = 400, detail: str = None):
        self.code, self.message, self.status, self.detail = code, message, status, detail

# 示例
raise BusinessError(3002, "样品编码已存在", 409, f"sample_code={code} 已被占用")
```

**数据库约束错误必须转为业务错误**，不能直接抛 500：

| MySQL 错误码 | 含义 | 转业务码 |
|---|---|---|
| 1062 | 唯一键冲突 | 3002 |
| 1451 | 外键被引用，禁止删除 | 4009 |
| 1452 | 外键引用不存在 | 4010 |
| 3819 | CHECK 约束失败 | 1001 |

### 8.2 前端

按 `code` 分支处理，而非 HTTP 状态码：

```typescript
switch (body.code) {
  case 0:      return body.data;
  case 2001:   /* 令牌过期，已在拦截器处理 */ break;
  case 2002:   ElMessage.error('权限不足'); break;
  case 3001:   /* 资源不存在，跳转列表页 */ break;
  case 1001:   /* 表单校验失败，回显 errors */ break;
  default:     ElMessage.error(body.message);
}
```
