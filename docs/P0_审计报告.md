## 3. 表结构与关联（复用主链）

`experiment_plans → experiment_plan_steps → processes → process_steps → process_samples → sample_transitions → measurements → measurement_points`，溯源侧 `source_files → source_file_occurrences → import_items`，结果侧 `derived_results`，审计 `audit_log`（多态 `entity_type/entity_id`，含 CHECK 约束枚举），快录侧 `quick_runs → quick_results / quick_steps / quick_revisions / quick_imports / quick_exports`。

- 主键均为稳定自增内部 ID；`process_code`、`sample_code` 等显示编号可改，关联不依赖显示编号（符合 `AGENTS.md` 约束）。
- 外键 95 个，删除保护策略侧重“拒绝删除”而非级联，未发现 `ON DELETE CASCADE` 的科学数据级联删除（迁移脚本无 `DROP TABLE/DROP COLUMN/TRUNCATE/DELETE FROM`，仅 `0010` 有 `MODIFY COLUMN` 扩宽 `step_kind`）。

## 5. 现有备份 / 恢复能力（关键缺口）

**已有**：`database/migrate.py:snapshot()`，在迁移前用 `START TRANSACTION WITH CONSISTENT SNAPSHOT`（REPEATABLE READ）逐表导出为 JSON + `schema.sql` + `manifest.json`（含行数），迁移后再做“行数与字段值不变”校验（`verify_original_values`）。

**缺口（P0 必须补）**：

1. 备份目录在项目内 `backups/`，磁盘损坏/误删项目目录会连带丢失。
2. 无 SHA-256 校验值，无法判断备份文件是否损坏。
3. 快照格式是自定义 JSON，**没有恢复脚本**，等于“只有备份文件，没有恢复能力”。
4. 备份不含 `storage/originals`（原件/Excel 原件），清单也未关联附件。
5. 无保留周期策略（41 个历史目录已堆积，且无清理依据）。
6. 无每日计划任务；迁移前备份无独立日志。
7. 迁移无“生产库人工确认”门禁：`python database/migrate.py` 默认即作用于生产库。
8. 无“升级前在副本上演练迁移”的标准流程。

## 6. 环境隔离现状（关键缺口）

- 应用环境的唯一区分手段是环境变量 `ALE_DB_NAME`（默认 `ale_workbench`）。`backend/.env` 当前**只**设置了 `ALE_JWT_SECRET` 与 `ALE_COOKIE_SECURE`，即默认就是生产库。
- `ale_app` 对 `ale_workbench` 拥有 `SELECT/INSERT/UPDATE/DELETE`。因此只要有人以开发/测试目的启动后端而忘记设 `ALE_DB_NAME`，**会直接写生产库**，不会报错。
- 现有护栏只在测试侧：`backend/tests/conftest.py:5` 要求 `ALE_REQUIRE_TEST_DB=1` 时库名以 `_test` 结尾；`database/migrate.py:1036` 只允许 `ale_workbench` 或 `*_test`；`database/setup_test_env.py:32` 拒绝目标为生产库。**应用进程侧没有任何护栏**。
- `ALE_ENVIRONMENT` 只影响界面标签，不校验库名。

## 7. 启动脚本与密钥

- `start-workbench.ps1` 硬编码 `ALE_DB_HOST/PORT`，只读探测 `metadata()`，不迁移、不强杀进程，端口占用时拒绝启动 —— 符合“不自动迁移”。
- 密钥与凭据：`backend/.env`、`database/.dbcreds`、`database/.appcreds`、`backend/.setup-code`、`backend/.ai-master-key` 全部在 `.gitignore`；实测 `git status` 无未跟踪凭据；README 已声明不提交 `mysql_data/`、`backups/`、`storage/`、`reports/`。
- 日志：`backend/app/main.py` 中间件只记录 request_id/method/path，不记录异常文本、请求体、SQL 参数；`hide_parameters=True`。符合“不把密码写日志”。

## 10. 结论

现有系统的写入路径、修订历史、删除保护、迁移校验做得比一般项目扎实：修订历史强制留痕、删除只允许空草稿、迁移前后有行数与字段校验、启动不自动迁移。真正的短板集中在**“备份不可证伪、恢复能力缺失、环境隔离靠自觉、生产迁移无门禁”**四点，因此 P0 的重点不是改表，而是补齐这四道闸门。
